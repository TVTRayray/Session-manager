# 04. 全文搜索浮层（对应 PRD-7 第 4 节）

## 与现有 `/` 搜索的区别

| | 现有 `/`（元数据搜索） | 新增 `Ctrl+F`（全文搜索） |
| :-- | :-- | :-- |
| 搜索范围 | 当前列表可见的 session_id / 摘要 / 时间 / 路径 | 所有已索引会话的**正文内容**（User/Assistant/工具调用文本） |
| 展现方式 | 状态栏内联一行，直接在原列表里高亮/跳转 | 独立的全屏浮层，带滚动结果列表 |
| 触发/退出 | `/` 进入，`Enter` 确认跳转，`Esc` 取消 | `Ctrl+F` 进入，`Esc` 关闭 |

两者并存、不合并，避免用户混淆"过滤当前列表"和"全局检索正文"这两种不同心智模型。

## 线框（浮层约占屏幕 84×32，居中）

```text
╭ Full-text Search ──────────────────────────────────────────────────────────────╮
│  🔍 登录态过期                                                                   │
│  ──────────────────────────────────────────────────────────────────────────── │
│  ▸ [demo-repo] 修复登录态过期问题                          Codex · 09-14 09:22  │
│      "...排查后发现 refresh token 过期时没有正确刷新，登录态过期后..."          │
│                                                                                  │
│    [infra-tools] 网关会话管理重构                          Pi    · 09-10 16:40  │
│      "...涉及到登录态过期的边界情况，需要补充单测..."                          │
│                                                                                  │
│    [python-script] 新彭楠-备煤日进及消...                  Pi    · 09-16 14:02  │
│      "...(3 more matches in this session)"                                     │
│                                                                                  │
│  ──────────────────────────────────────────────────────────────────────────── │
│  索引状态：已完成 128/128 会话              ↑↓ 选择   Enter 跳转   Esc 关闭     │
╰──────────────────────────────────────────────────────────────────────────────────╯
```

* 顶部是常驻输入框（🔍 图标 + 输入内容），输入即实时刷新下方结果（防抖，避免每个字符都触发一次数据库查询）。
* 结果列表每条包含：会话标题/项目、来源引擎、时间、一段命中片段（关键词加粗/高亮）；同一会话命中多处时只展示最相关一条 + `(N more matches)` 提示，不铺开所有命中行。
* 当前选中结果左侧用 `▸` 标记（与列表面板的高亮反色风格保持一致，这里用箭头是因为浮层内是纵向单列，不需要整行反色以保留片段的高亮颜色可读性）。
* 底部一行常驻：左侧显示索引构建进度（未完成时显示 `索引中 42/128`），右侧是操作提示。

## 空状态 / 索引未就绪

```text
╭ Full-text Search ──────────────────────────────────────────────────────────────╮
│  🔍 一个不存在的关键词                                                          │
│  ──────────────────────────────────────────────────────────────────────────── │
│                                                                                  │
│                         No matches found.                                      │
│                                                                                  │
│  ──────────────────────────────────────────────────────────────────────────── │
│  索引状态：已完成 128/128 会话              ↑↓ 选择   Enter 跳转   Esc 关闭     │
╰──────────────────────────────────────────────────────────────────────────────────╯
```

索引尚未构建完成时，允许照常输入搜索（只是结果集不完整），状态行明确提示 `索引中 N/M`，不阻塞交互、不弹错误。

## 跳转行为

选中某条结果按 `Enter`：

1. 关闭浮层。
2. 若命中会话所属引擎与当前 `active_engine` 不同，自动切换引擎 Tab。
3. 列表面板自动选中该会话所在的树节点（含展开必要的父分组）。
4. 详情面板（`Detail`）视口自动滚动到命中内容所在的大致位置（对应 PRD-7 里提到的"定位到第 N 个 transcript_block"能力）。

## 待确认问题

* 浮层尺寸是否需要随终端大小自适应更激进的比例（比如超宽终端下限制最大宽度，避免一行文字过长难以扫读）？本设计先给出比例基线（约 84% 宽 / 80% 高），实现时可按 `centered_rect` 现有的最小宽高兜底逻辑复用。
* 是否需要在结果列表里也支持 `fav:`/`tag:` 过滤语法（与 `02-favorites-tags.md` 的语法保持一致）？建议后续统一，但非本阶段必须项。
