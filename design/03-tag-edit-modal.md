# 03. 标签编辑弹窗（对应 PRD-7 第 2 节）

## 触发
选中某个会话叶子节点，按 `t`。视觉与交互风格对齐现有 Delete 确认弹窗（居中浮层、圆角边框、底部按钮组可用方向键/Tab 切焦点）。

## 线框（约 70×9，居中浮层）

```text
╭ Edit Tags ──────────────────────────────────────────────────────╮
│                                                                    │
│  Session: 019ff00e-623f-7018-8d1d...                              │
│                                                                    │
│  Tags (comma separated):                                          │
│  bug, 紧急_                                                        │
│                                                                    │
│                    [ Cancel ]      Save                            │
╰────────────────────────────────────────────────────────────────────╯
```

* 打开时输入框预填当前已有标签（逗号分隔），光标停在末尾（下划线 `_` 表示光标位置）。
* 新建标签时输入框为空，占位提示 `type tags, separated by comma`。
* 底部按钮组沿用 `delete_button_span` 的高亮规则：聚焦的按钮外面套 `[ ]`，未聚焦的纯文字弱化色。

## 交互状态机

| 按键 | 行为 |
| :-- | :-- |
| 可打印字符 | 追加到输入框 |
| `Backspace` | 删除输入框末尾字符 |
| `Tab` / `←` `→` | 在"输入框 → Cancel → Save"之间循环切焦点 |
| `Enter`（焦点在输入框或 Save） | 提交：解析逗号分隔标签（去除首尾空格、去重、忽略空字符串），写入 `state.db`，关闭弹窗，列表立即刷新标签徽标 |
| `Enter`（焦点在 Cancel） / `Esc`（任意焦点） | 放弃修改，关闭弹窗 |

## 边界情况

* 输入内容清空后直接 `Save`：视为"清除该会话全部标签"，不是取消操作，需要在弹窗底部加一行弱化提示 `Leave empty to clear all tags`，避免用户误解。
* 单个标签长度 / 数量不做硬限制，仅在列表渲染时按可用宽度截断显示（不影响存储的完整数据）。

## 待确认问题
